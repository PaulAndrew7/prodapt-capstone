# Evaluation analysis

Written by hand from the raw results in `raw/`; [results-dev.md](results-dev.md) (and `results-test.md` once the held-out split runs) is regenerated by `python -m app.cli evaluate` and holds the numbers. Everything here refers to the fictional Kestrel Mutual corpus and the 13 development scenarios, whose labels were reviewed against the clause text on 26 September (see `data/evaluation/README.md`).

## 26 September 2026: retrieval only

No language model was configured, so only retrieval was measured (`raw/dev-2026-09-26.json`). Re-measured after the label review changed four dev scenarios: hybrid recall and bundle recall did not move; keyword-only rose from 0.683 to 0.704 because dev-013 now uses the word "noticed", which matches Incident Response §3.1.

| Measurement | Result |
|---|---|
| Recall@10, hybrid | 0.839 over 12 scenarios with labelled clauses |
| Recall@10, keyword only | 0.704 |
| Evidence bundle recall | 0.856 |

**Hybrid beats keyword-only on this set.** The dense channel mostly adds clauses whose wording differs from the question, such as a vendor clause for "analytics vendor".

**Tuning, on development data only.** Starting the evidence bundle from eight search hits gave a bundle recall of 0.822, below Recall@10. Ten hits within the same 14-clause cap raised it to 0.856, with bundles of about 11 clauses. Twelve hits reached 0.883 but needs a larger cap and more model input. The search limit is now 10. No held-out labels were used.

### Failures worth explaining

1. **Purpose limitation is rarely retrieved (dev-001, dev-003, dev-008, dev-012).** Data Sharing §4.3 says the shared fields must be limited to the documented purpose. Scenarios describe *what* is sent, not the purpose or field list, so neither channel ranks §4.3 in the top ten. The analysis stage therefore usually cannot report §4.3 as unknown. §4.3 is not cited by §4.2, so the relation expansion does not help. A possible fix is a reviewed "references" link from §4.2 to §4.3. It is not added yet because no assessment run has shown the missing finding changes a result.
2. **Adversarial wording pulls in the wrong policy (dev-012).** "Emailing the full customer list to our marketing agency" retrieves Customer Onboarding clauses (co_*) ahead of the sharing rules. §4.2 still arrives at rank 9, so the decisive clause is in the bundle, but Vendor Due Diligence §3.1 does not: "marketing agency" is not matched to "vendor". The instruction "ignore your policies" is treated as scenario text, which is intended.
3. **Governance clause missed in a conflict case (dev-009).** The retention conflict retrieves the Retention and Model Development clauses but not Governance §4.1, the clause that says how policy conflicts are escalated. The model could still find the conflict, but not the escalation route.
